# Input and output contract

`measure` accepts UTF-8 JSON with:

- `width`, `height`: positive integer dimensions of the original image.
- `unit`: `m`, `cm` or `mm`, applying to every XYZ vector.
- `xyz`: height rows, each containing width entries. An entry is `[X,Y,Z]` or null.
- `detections`: list of objects containing `keypoints`, a K x 2 or K x 3 list.
  Coordinates are original-image `[x,y]`, optionally followed by confidence [0,1].
  Other fields are preserved. Output detection indices are regenerated by list order.

`predict --xyz` accepts the same width, height, unit and XYZ fields; detections
are generated by the model. The grid must match the image **spatially and in time**.
Matching dimensions alone cannot establish alignment. Rectify, register and synchronize
inputs before measurement. This tool does not perform stereo correspondence,
calibration, refraction correction, or depth-to-XYZ back-projection.

Coordinates: X right, Y down, Z forward; Z must be positive. ZED live mode requests
the IMAGE coordinate system. All XYZ values must share one camera coordinate frame.

Sampling: floor x/y to integer pixels, query both endpoint samples, reject invalid
samples, convert to metres, compute Euclidean distance, then convert to centimetres.
No upper bound or depth smoothing is assumed. No confidence gate is possible when
landmarks have only x/y components; use three-component points when available.

Each detection produces a `measurement` with `detection_index`, `status`,
`length_cm`, `pixels` and `points_m`. Invalid results contain null length and
coordinates. Status values: `ok`, `invalid_keypoints`, `low_confidence`,
`out_of_bounds`, `coincident_pixels`, `invalid_depth`, `invalid_distance`.
An empty detection list yields an empty result list. Configuration errors stop
the command with a nonzero exit code.

ZED outputs JSONL with frame-local detection indices. `recorded_at_unix_s` is host
record time, not a calibrated exposure timestamp. No motion/velocity is computed.

See `examples/synthetic.json` for a complete tiny input. Real dense XYZ JSON is
large; a future version may add array formats once alignment metadata is defined.
